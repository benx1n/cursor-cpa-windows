# Cursor 插件 0.6.6-windows.2

本版本基于 0.6.6，适配 Windows amd64 EasyCPA / CLIProxyAPI，改善授权网络与 Codex 客户端工具调用。插件以 DLL 形式安装，无需替换核心程序。安装步骤见 [Windows EasyCPA](../windows-easycpa.md)。

## Windows 安装与授权

- 增加 DLL 构建、手动安装包、商店格式 ZIP、SHA-256 校验、升级备份和卸载脚本，以及 Linux / Windows CI 构建。
- OAuth 轮询、刷新、模型发现和推理继承宿主上游代理；账号 `proxy_url` 可覆盖全局设置。
- OAuth 轮询对暂时网络错误、408、429 和 5xx 最多额外重试 3 次，正常等待会重置连续错误计数。证书错误、401 和 403 不重试。
- 授权失败消息不再包含 OAuth 轮询 URL 或 PKCE verifier。

## 思考与工具调用

- 思考事件独立输出到 `reasoning_content`，纳入估算用量和输出预算，由宿主转换为 Responses 思考摘要事件。
- 完整请求和检查点续轮均提示使用 `opencodex-responses` 暴露的客户端工具；推荐项按当前工具目录匹配，包含带命名空间的工具名。
- 拒绝原生文本写入、删除和目录读取，并补充已有读取、搜索及终端拒绝的客户端工具指引。网关不执行这些文件操作，图片生成的隔离二进制写入路径保留。
- 无客户端工具时，普通聊天提示模型直接返回文本，所需外部操作不可用时说明限制。
- 带工具请求默认无进展超时为 5 分钟，普通请求仍为 90 秒；工具参数和工具开始事件更新进度，纯心跳不无限延长请求。保留 30 秒数据/帧静默检查和 15 分钟总截止时间。
- 上游排空和清理完成后才输出最终结束标记。

思考透传及无客户端工具提示参考 [kilolonion/cursor-cpa-plugin](https://github.com/kilolonion/cursor-cpa-plugin) 的 MIT 实现，来源提交与署名见 [THIRD_PARTY_NOTICES](../../THIRD_PARTY_NOTICES.md)。保留 0.6.6 的上下文、排队、Blob 和输出预算。

## 验证

- Windows CGO `go test -shuffle=on -count=1 ./...`、`go vet ./...`、DLL 构建及 actionlint 通过。
- 安装脚本验证覆盖预演、校验失败拒绝、升级备份、卸载和含方括号的路径。
- 在 Windows EasyCPA v0.2.101 / CLIProxyAPI v8.0.27 上加载并注册 DLL，OAuth、管理页和现有账号正常工作。
- 端到端验收经宿主 `/v1/responses` 调用客户端 custom `apply_patch`，创建 HTML 并回传工具结果，两轮均收到思考摘要及 `response.completed`。

端到端验收覆盖小文件创建和结果续轮，大文件流程仍需进一步验证。提示与运行时拒绝无法保证模型每次都成功选择客户端工具。

## 宿主限制

CLIProxyAPI 8.0.27 仍可能在客户端收到完成事件后错误记录 HTTP 499；流式桥接未完整保留插件 `error_details`，部分上游超时仍显示 HTTP 500。结束顺序调整不能代替核心修复，本版本未修改核心程序。

Token 统计为本地估算，不能视作 Cursor 实际账单或剩余额度。
